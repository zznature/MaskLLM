## 2️⃣ NaN 根本原因深度分析

### **为什么超保守训练推进了 160 次仍然 NaN？**

#### **核心矛盾**

```
SparseGPT 2:4 固定 mask → 与最优 mask 冲突 → Reg loss 持续上升
                                                        ↓
                            即使增速很慢 (+1.6/iter)，累积仍会导致数值问题
                                                        ↓
                            Temperature 降低 → Mask 趋向确定 → 梯度分布变化
                                                        ↓
                            BF16 精度不足 → 局部梯度极值 → NaN
```

#### **关键发现**

1. **Reg loss 绝对值很高**:
   ```
   iter 1310: 9,032 (vs 初始 7,000-8,000)
   累积增长: ~2000 (from iter 0)
   ```

2. **Temperature 仍在危险区**:
   ```
   当前: 2.364
   危险区: 1.8-2.5 (mask 软→硬转换期)
   安全区: >2.5 或 <1.5
   ```

3. **BF16 的系统性限制**:
   - 即使 grad norm 稳定，个别参数的梯度可能极端
   - BF16 动态范围有限（~10^-38 to 10^38）
   - Temperature 2.0-2.5 范围内，mask logits 可能产生极端值

### **方案 A: 极限保守 BF16 (不推荐)**

#### **策略**
从 iter 1310 继续，使用更极端的保守参数。

#### **参数修改**

#### **预期**
- ✅ Mask 更新极慢，Reg loss 增速 <+1/iter
- ✅ Temperature 更慢下降
- ⚠️ **风险**: 可能在 iter 1400-1500 再次 NaN

#### **适用场景**

### **方案 B: FP32 继续训练 (强烈推荐 ⭐⭐⭐⭐⭐)**

#### **策略**
从 iter 1310 切换到 FP32，使用适中的参数，彻底解决 NaN。

#### **技术方案**

**步骤 1: 精度转换**
```bash
# 从 BF16 checkpoint (iter 1310) 加载
# PyTorch 自动转换权重: bf16 → fp32
# 不加载优化器: --no-load-optim
```

**步骤 2: 参数设置**
```bash
# 不需要极保守（FP32 稳定性极高）
--lr 1.5e-5           # 保持超保守的 base LR
--min-lr 1.5e-6
--lr-mult 5           # FP32 可以支持更快的 mask 更新
--clip-grad 0.5       # 稍微放宽（FP32 裕度大）

--recompute-activations  # 控制显存
--no-use-flash-attn      # FP32 不支持 Flash Attention
```

**步骤 3: 显存优化**
```bash
--recompute-activations
--recompute-granularity full
--no-save-optim  # 减小 checkpoint 大小
```

#### **预期效果**

| 指标 | 预期值 |
|------|--------|
| **成功率** | 95% (几乎确定) |
| **剩余迭代** | 690 (1310 → 2000) |

| **显存** | 65-70GB / 80GB |

| **NaN 风险** | <2% (极低) |

#### **优势分析**

✅ **彻底解决问题**:
- FP32 动态范围: 10^-38 to 10^38 (vs bf16 的 10^-8 to 10^4)
- 完全避免数值下溢/溢出
- Temperature 任何值都稳定

✅ **保留训练进展**:
- 从 iter 1310 继续（已完成 65.5%）
- 模型权重自动转换，无损失
- Mask 优化状态保留

✅ **可预测性**:
- 训练轨迹可控
- 可以准确预估完成时间
- 无需担心随机 NaN

#### **劣势**

❌ **速度慢**:
- 每次迭代 ~365秒 (vs bf16 220秒)
- 总时间增加 ~30小时

❌ **显存增加**:
- 65-70GB (vs bf16 53GB)
- 但 80GB 显存足够

#### **适用场景** (推荐)
- ✅ **首选方案**: 稳定性 > 速度

```
                             ↓
```

#### **实施**
```bash

# 无 SparseGPT 约束，Mask 自由演化
```

#### **优势**
- ✅ 根本解决 SparseGPT 冲突

#### **劣势**
- ❌ 需要完整 2000 iters

- ❌ 放弃所有现有进展

#### **适用场景**
