## 🔍 深度分析: lr_mult提升空间

### 1. 历史对比分析

**参考Llama2成功案例** (`llama2_7b_mask_only_tp8_c4.sh`):
- lr_mult: **10** (远高于我们的2.0)
- weight_reg: 2e-6 (远低于我们的1.5e-5)
- 稳定性方程: 2e-6 / (10 × 2e-5) = **0.01** (极低但成功)

**我们的历史尝试**:
| 训练 | lr_mult | weight_reg | 稳定性 | 结果 |
|------|---------|------------|--------|------|

| Plan A | 3.0 | 1e-6 | 0.022 | 失败 @ iter 1310 |

| **Planned (1000-2000)** | **3.0** | **1.5e-5** | **0.33** | **?** |

### 2. lr_mult上限分析

**理论上限**: 基于稳定性方程

```
稳定性 = weight_reg / (lr_mult × base_lr)
稳定性 ≥ 0.2 (BF16安全下限, 基于历史数据)

lr_mult ≤ weight_reg / (0.2 × base_lr)
lr_mult ≤ 1.5e-5 / (0.2 × 1.5e-5)
lr_mult ≤ 5.0
```

**实践上限**: 基于当前状态

当前 @ iter 1000:
- max_prob: 0.566
- mask仍在活跃调整中
- Reg loss: 8,216 (增长率2.87 /iter)

**可行的lr_mult范围**:
- ✅ **保守**: 3.0 (计划中, 稳定性0.33)
- ✅ **适中**: 4.0 (稳定性0.25)
- ⚠️ **激进**: 5.0 (稳定性0.20, 理论极限)
- 🔴 **过度**: >5.0 (稳定性<0.2, 危险)

## 💡 其他参数优化空间

### 1. weight_reg (正则化强度)

**当前**: 1.5e-5

**分析**:
- 如果提高weight_reg → 稳定性提高 → 但mask学习变慢 ❌
- 如果降低weight_reg → 稳定性降低 → 但可以提高lr_mult ✅

**优化方案**: 如果选择更高的lr_mult (4.0或5.0), 可以考虑:

```bash
# 方案B优化版
lr_mult: 4.0
weight_reg: 2.0e-5    # ← 提高33% (补偿稳定性降低)
稳定性: 2.0e-5 / (4.0 × 1.5e-5) = 0.33  # 恢复到方案A水平
```

**效果**:
- ✅ 保持稳定性在0.33 (安全)
- ✅ Mask LR仍为6.0e-5 (快速)
- ✅ Reg loss增长更可控
- ✅ **最佳平衡点** ⭐⭐

---

## 🎓 关键洞察

### 1. lr_mult vs weight_reg的tradeoff

**核心关系**:
```
稳定性 = weight_reg / (lr_mult × base_lr)
```

**策略**:
- 想要更高lr_mult → 需要更高weight_reg来维持稳定性
- **B优化方案**正是利用了这个关系

### 2. 训练阶段的动态调整

**理想的lr_mult轨迹**:
- 早期 (0-500): lr_mult=4-5 (快速探索)
- 中期 (500-1500): lr_mult=3-4 (精调)
- 后期 (1500-2000): lr_mult=2-3 (稳定)

**我们的实际**:
- 早期 (75-1000): lr_mult=2.0 (太保守) ❌
- 中期 (1000-2000): lr_mult=3.0或4.0 (合适) ✅

**结论**: 早期偏保守导致进度慢，现在应该补偿

### 3. 稳定性方程0.33是一个"甜点"

**历史数据**:
- <0.20: 高风险
- 0.20-0.30: 中等风险
- **0.30-0.50**: 低风险 (甜点) ✅
- >0.50: 过度保守

**B优化方案**维持在0.33，正好在甜点中心
